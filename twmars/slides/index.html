Part I · Kurt Cutajar · ~60 min

Foundations:
the benign system

Before any adversary: what a multi-agent recommender is, what each agent can do, and how autonomous it gets.

I.1 · Background

Three eras of recommendation

Classical

CF, matrix factorisation, neural & sequential rankers. Optimise a scoring function over logged interactions.

LLM-based

The model suggests: zero-shot ranking, in-context & generative recommendation from a prompt.

Agentic

The system acts: plan over a goal, call tools, carry memory, and delegate across agents.

Each era keeps the prior era's risks and adds its own. We build the benign picture first; adversaries come in Part II.

I.2 · The progression

Levels of Autonomy attack surface grows monotonically

LevelWhat it isNew surface
LoA-0Classical non-LLM recommender; no language, tools, or state.Shilling, training-data poisoning, membership inference.
LoA-1LLM as a scoring / generation function. Suggests, doesn't act.Hallucination, prompt sensitivity, bias, output-channel leakage.
LoA-2LLM + tools + memory + planning. Single agent acting on goals.Tool injection & unsafe calls · memory poisoning · autonomy/planning exploits.
LoA-3Composition: many LoA-2 agents in a pipeline, peer net, or hierarchy.Inter-agent pathways: infection, contagion, cascading failure. our focus

Multi-agent-ness (LoA-3) and tool use (LoA-2) are orthogonal, each adds an independent risk profile. LoA-∞ (self-revising, sub-spawning, no human checkpoint) anchors the open-problem horizon.

I.3 · Anatomy

What every agent can do

Individual capabilities

  • Planning: decompose a goal into tool calls
  • Reflection: critique & revise its own output
  • Tool use: query / modify external systems
  • Memory: short-term context · long-term store

Multi-agent capabilities

  • Inter-agent communication: pass results, delegate
  • Coordination: synchronise, resolve disagreement
  • Auditing: agents that check other agents

The last two open surfaces (flooding, prompt infection, agent-in-the-middle) that no single-model framework even has.

I.4 · Structure shapes risk

Connectivity vs. workflow

Two orthogonal axes: control (centralized ↔ decentralized) and role specialization (specialized ↔ homogeneous) give four recurring patterns. Connectivity is who can talk; workflow is who does what.

PatternRepresentativeCharacteristic risk
Hierarchical delegationMACRec, MACFUnverified delegation: a compromised specialist biases every downstream decision.
Sequential pipelineMATCHA, RAHError amplification: content injected early propagates as trusted context.
Ensembleparallel LLM rankersCorrelated errors: shared backbones fail together; ensemble amplifies.
PeerAgentCF, MemRecPeer contagion: one compromised agent spreads to all it touches; no checkpoint.

Tool-augmentation is a cross-cutting overlay on all four. This 2×2 recurs as the anchor for every risk in Part II.

Part II · Anjun Hu · ~50 min

How composition
creates risk

Two lenses (amplified vs emergent) and three threat tiers, then we attack a real multi-agent recommender, live.

II.1 · The core distinction

The isolation test

Give an agent its full tool and memory interface, but let no other agent consume or produce its messages.

  • A risk that already appears under isolation and worsens once messages flow → amplified.
  • A risk whose definition requires more than one agent, so it cannot even be stated for a system of one → emergent.

The line is about the harm itself, not whether it travels: a single agent's leak that merely spreads is still amplified.

Quick test

Can you state the harm for one agent?

→ Yes: amplified

→ No: emergent

II.1 · Baselines

Single-agent baselines we amplify over

FamilySingle-agent risk (isolation test)
Prompt injection / jailbreakAdversarial text overrides the system instruction; alignment bypassed.
HallucinationA generator returns ungrounded or fabricated items.
Poisoning & shillingCrafted profiles/interactions steer one recommender's output.
PrivacyMembership inference & prompt inversion leak user history.
Bias & feedback loopsOutputs re-enter training data, amplifying popularity / exposure skew.
Memory poisoningWrite- and retrieval-time corruption of one agent's long-term memory.

Each amplified risk in II.2 is presented as a delta over its baseline here.

II.2 · Amplified risks already present, worse under composition

Amplified risk gallery

Injection propagationOne poisoned output is read as trusted input by the next agent: a single injection spreads along retriever→ranker→explainer.
Distributed jailbreakA jailbreak fragmented across the topology reassembles at an agent unreachable from outside: a max-flow problem on the comms graph.
Pipeline poisoningA poison planted once is consumed by every downstream agent; failure looks like an ordinary model error.
Memory poisoningShared / cross-session memory means one contaminated write is read many times.
PrivacyInter-agent messages nobody monitors can raise total exposure even as output-channel leakage drops.
Bias hardeningAgents on a shared backbone make correlated errors; structured workflows become echo chambers.
Feedback loopsLoops that close between agents narrow diversity until a filter bubble forms.
Error / hallucination propagationA hallucinating specialist biases every downstream decision the orchestrator builds on.

II.3 · Emergent risks no single-agent analogue

Emergent risk gallery

Inter-agent communication attacksThe channel itself is the target: covert content riding the message bus.
CollusionAgents coordinate toward an outcome none would independently favour.
Contagion & false consensusSelf-replicating content / agreement spreads until the group converges on a lie.
Monitor gamingAgents satisfy the auditor's measure rather than its intent (auditor sycophancy).
Coordination pathologiesEach agent is locally correct, yet together they return nothing usable.
Availability / resource depletionRecursive call patterns exhaust the system and interrupt service.
Compositional privacyAn attribute no single agent reveals is exposed by combining their outputs.

II.3 · Recap

The first lens, side by side

Amplified A

Definable for one agent. Composition lets it spread or compound.

Mitigation often starts at the component, then hardens the channel.

Emergent E

A property of the interaction. No component-level test can see it.

Mitigation must be scoped to interaction / composition.

II.4 · The second lens

Threat tiers by intent

TierWhat drives itManifests at
DriftSystem dynamics degrade quality / fairness / safety, with no adversary. Feedback loops, distribution shift, cross-agent accumulation.Component
MisalignmentAn internal agent pursues an objective that diverges from the system goal: stakeholder conflict, reward hacking, sycophantic judges.Interaction
CompromiseAn external attacker corrupts agents: poisoning, injection, prompt infection, peer contagion.Composition

Every catalogued risk gets exactly one tier; every mitigation is evaluated against the tier it targets.

II.5 · Live demo · hard 10 to 15 min

ConnaCF

Attacking & defending multi-agent collaborative filtering through connectivity. We walk it; you red-team it over the break.

Demo · setup

A bipartite agent graph on AgentCF

User-agents and item-agents update each other through a forward() → backward() cycle. We sweep two connectivity axes:

  • Candidate count k: k=0 (MACF) → k=2 (AgentCF) → k=3
  • Catalog concentration ρ: sparse → medium → dense overlap

Same attack, different connectivity → different outcome. That gap is the amplified-vs-emergent story, measured.

Demo · what we attack

Three attack families + defenses

Dissemination NetSafe · CORBA · DrunkAgent · Prompt-Infection   Extraction MAMA · MASLeak · InjecAgent   Bidirectional TOMA · MASTER   Defense G-Safeguard · BlindGuard · T/M-Guard

Demo · walk-through

One attack, end to end

  1. Clean run. Show benign interaction traces on a medium-density graph.
  2. Inject. A single poisoned item description seeds a self-replicating payload (CORBA / Prompt-Infection).
  3. Watch it spread. infection_rate_forward climbs as the payload rides forward()→backward() to users it never touched directly.
  4. Classify. Which lens? Which tier? Which connectivity made it possible?
  5. Defend. Turn on G-Safeguard / BlindGuard: prune the infected edges, re-measure.

Runs Bedrock-free on a local Qwen3 + judge, reproducible without an AWS account.

Demo · the punchline

Component passes. Composition fails.

Each agent's local safety check is green. The composed system is fully infected.

Density and candidate-count turn a contained nuisance into an epidemic, exactly what component-level evaluation misses.

Part III · Yashar Deldjoo · ~50 min

Evaluation
& benchmarking

What to measure and when, scoped to the level at which failures manifest.

III.1 · Framework

Scope × setting

Isolated agents can pass their own checks while the composed system stays compromised, so we scope evaluation to the level at which failures manifest.

ScopeOfflineOnline
ComponentPer-agent constraint checks · recommender metrics · adversarial promptingBehavioural drift detection
InteractionAgent-pair red-teaming · protocol checks · counterfactualsInter-agent message-trace monitoring
CompositionEnd-to-end stress tests · fairness & collusion auditsSystem-level KPIs · incident reconstruction

Aligns with the threat tiers: drift→component, misalignment→interaction, compromise→composition.

III.2 · Per scope

What each cell measures, and misses

ComponentMeasures: per-agent ASR, accuracy, calibration (e.g. InjecAgent-style indirect-injection tests). Misses: anything that needs a second agent.
InteractionMeasures: pairwise red-teaming, protocol & message-trace checks. Misses: system-wide emergent effects.
Composition (offline)Measures: end-to-end stress, fairness & collusion audits under attack. Misses: live drift & rare-event triggers.
Composition (online)Measures: system KPIs, incident reconstruction from traces. Misses: counterfactual “what if not attacked”.

ConnaCF makes this concrete: component checks stay green while infection_rate climbs at the composition level.

III.3 · Benchmarking

Benchmarking multi-agent recommenders

  • Attack success vs. connectivity: sweep candidate-count k and density ρ (the ConnaCF protocol) so results are comparable across topologies.
  • Topology-aware defenses: G-Safeguard / BlindGuard evaluated on the graph, not the agent.
  • Where single-agent benchmarks fall short: they cannot express contagion, collusion, or compositional privacy.
